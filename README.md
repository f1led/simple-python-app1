# CI/CD Pipeline Documentation

Данный проект демонстрирует реализацию полноценного CI/CD пайплайна с использованием Jenkins, Docker и Git.

## Архитектура пайплайна
Пайплайн разбит на логические этапы:
1. **Checkout**: Загрузка исходного кода из репозитория.
2. **Tests**: Условный этап (параметр `RUN_TESTS`). Разворачивает виртуальное окружение Python и прогоняет модульные тесты `unittest`.
3. **Build and Push**: Сборка Docker-образа приложения и отправка в Docker Hub.
4. **Условные деплои**:
   - `Deploy to Dev`: Поднимает контейнер на порту **5050**.
   - `Deploy to Staging`: Поднимает контейнер на порту **5051**.
5. **Approve Production**: Этап, приостанавливающий сборку до получения ручного подтверждения (ручной аппрув).
6. **Tag Version**: Автоматическое создание Git-тега релизной сборки (срабатывает только для `production`).
7. **Deploy to Production**: Развертывание в продакшн-окружении на порту **5052**.

## Уведомления и плагины
- Уведомления о результатах сборки отправляются на почту администратора с помощью плагина `Email Extension` (`emailext`).
- Для визуализации процесса рекомендуется использовать **Blue Ocean**.

## Ограничения по портам
Так как порты 8080, 8081, 8082, 8083, 8090, 80, 443, 8100, 8101, 8102, 9113, 2222, 2223, 8888, 3000 и 5432 были заняты, приложение использует динамическую конфигурацию через внутренний порт 5000, проброшенный наружу как `5050` (Dev), `5051` (Staging) или `5052` (Prod).
